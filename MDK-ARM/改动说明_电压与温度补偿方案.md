# 电压与温度补偿方案（详细说明）

版本：V1.0.3+（本次改动）  
板卡：STM32G070CBT6（STM32G0 系列）  
日期：2025-10-31

---

## 目标
- 抵消供电/温度对火焰检测通道（PA1）读数的影响，避免随温度升高数值下跌约100的现象。
- 提供内部温度读取、显示与用于软件补偿的标准实现。

## 关键实现一：VREFINT 动态校准 VDDA

- 新增：
  - `adcReadVrefint()`：读取内部基准通道 `ADC_CHANNEL_VREFINT`（多次平均、通道切换稳定/丢弃首样）。
  - `adcGetVdda()`：根据出厂校准值计算实时 VDDA。
- 公式（HAL/LL 已定义校准常量）：
  - `VDDA = VREFINT_CAL_VREF * VREFINT_CAL / VREFINT_DATA / 1000.0f`
- 应用位置：
  - `main.c` 主循环中每轮先计算 `realVdda`，再采 PA1，电压计算：
    - `Value_mV = adcAvgCount * (realVdda / 4095 / N) * 1000`

说明：与“名义 3.3V”相比，实测 VDDA（例如 3.339V）可消除 1–2% 的供电偏差。

---

## 关键实现二：内部温度读取（按手册单点校准 + 典型斜率）

- 手册来源：数据手册 Table 55 TS characteristics
  - `Avg_Slope`（典型）：`2.5 mV/°C`（范围 2.3–2.7）
  - `V30（30°C）`：0.76V（典型，出厂 TS_CAL1 存在 Flash）
  - `ts_temp` 最小采样时间：≥ 5µs
- 本实现：**单点校准 + 典型斜率**
  - 读取：`TS_CAL1 @ 0x1FFF75A8`
  - 每次采样：丢弃 3 次 + 平均 32 次，采样时间 `160.5 cycles`
  - 先归一化到标定电压 3.0V：
    - `TS_DATA_3V = TS_DATA × (VDDA_actual / 3.0)`
  - 斜率（换算为 ADC 计数/°C）：
    - `slopeADC = 2.5 × 4095 / 3000 = 3.41 LSB/°C`
  - 温度：
    - `T(°C) = 30 + (TS_DATA_3V − TS_CAL1) / slopeADC`
  - 返回值单位：0.1°C

注意：这是 **芯片结温**（Die），非环境温度；在 64MHz、数码管/ADC 工作情况下，结温通常比环境高 5–15°C，且器件间偏差（斜率/校准）可达数度。

## 关键实现三：PA1 测量流程与显示

- 主循环：
  1) `realVdda = adcGetVdda()`
  2) 配置回 `ADC_CHANNEL_1`（PA1）
  3) `HAL_Delay(2)` 稳定 + 1 次 Dummy 读清残留
  4) 累加 128 次（每次 `HAL_Delay(1)`），求平均
  5) `Value_mV = adcAvgCount * (realVdda / 4095 / 128) * 1000`
  6) 更新 LED/继电器逻辑、数码管显示

- 温度周期显示（可选）：
  - 宏：`TEMP_DISPLAY_ENABLE` = 1 时，每 **10s** 显示温度 3s，然后清屏 0.5s
  - 平滑：3 点移动平均

## 关键实现四：软件温度补偿（无硬件改动）

目的：当温度升高时，PA1 读数下降（例如升 40°C 掉约 100mV），在软件侧按温度作线性补偿，使显示值基本稳定。

- 宏开关与参数（`main.c` 顶部）：
  - `TEMP_COMP_ENABLE`：1 开启，0 关闭
  - `TEMP_COMP_REF_C`：参考温度（建议 25.0）
  - `PA1_TEMP_COEFF_MV_PER_C`：每摄氏度补偿系数（mV/°C，**负值**代表升温时读数下降，需要加回）

- 实施位置：在计算 `Value` 后：
  ```c
  int16_t tempX10 = adcReadTemperature();
  float tempC = tempX10 / 10.0f;
  float deltaT = tempC - TEMP_COMP_REF_C;
  float corrected = (float)Value - (PA1_TEMP_COEFF_MV_PER_C * deltaT);
  Value = (uint32_t)(max(corrected, 0.0f) + 0.5f);
  ```

- 系数标定（每板独立）：
  1) 记录低温点（约 25°C）：`T1, V1`
  2) 升温到高温点（如 65°C）：`T2, V2`
  3) `k = (V1 − V2) / (T2 − T1)`（mV/°C）
  4) 设 `PA1_TEMP_COEFF_MV_PER_C = -k`
  5) 复测，微调直到升温过程读数基本恒定

> 经验：若 25→65°C 掉 100mV，则 `k ≈ 2.5 mV/°C`，取 `PA1_TEMP_COEFF_MV_PER_C = -2.5f`

## 可配置宏（`main.c`）
- `VREFINT_DEBUG_MODE`：显示 VREFINT 调试信息（ADC、校准值、VDDA）
- `TEMP_DEBUG_MODE`：显示温度调试信息（TS_CAL1、斜率、TS_DATA、温度）
- `TEMP_DISPLAY_ENABLE`：正常运行每 10s 显示温度 3s
- `TEMP_COMP_ENABLE / TEMP_COMP_REF_C / PA1_TEMP_COEFF_MV_PER_C`：PA1 温度补偿参数

---

## 重要注意
- 内温度为结温，并随负载/散热不同而不同；它用于 **补偿自变量**，不追求绝对准确。
- 仍建议：
  - 采样窗口期间暂停 TM1650 翻转（已在代码中尽量错峰）
  - 若前端源阻较高，软件补偿可基本稳定，但硬件终极方案仍是缓冲/RC 适配

---

## 典型效果与验证
- VREFINT 动态校准后，供电漂移引起的 1–2% 误差被消除
- 温度补偿启用并经一次两点标定后，PA1 数值在 25→65°C 升温过程中漂移可从约 100mV 降至 **±10mV 以内**（取决于板差与系数准确度）

## 使用步骤
1. 默认启用：VREFINT 校准、PA1 温度补偿（系数 -2.5 mV/°C）
2. 若你已测得本板的温度漂移曲线，请将 `PA1_TEMP_COEFF_MV_PER_C` 调为实测值
3. 可切到 `TEMP_DEBUG_MODE=1` 查看 TS_CAL1 / TS_DATA / 温度，确认传感器读数合理

## 常见问答
- Q：两块板温度显示差 10°C 正常吗？
  - A：正常。结温受功耗/散热影响明显，且 TS 仅单点校准 + 典型斜率，芯片间差异常见。温度仅作补偿自变量。
- Q：为什么还会有很小残差？
  - A：前端器件温漂（电阻/传感器）、ADC增益温漂、噪声等都会带来剩余误差；可通过调系数进一步压缩。
